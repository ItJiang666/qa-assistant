# 干净机器验收清单

在一台**没装过这个项目**的机器上，只照 [README](../README.md) 走一遍，
确认别人真的能跑起来。

**为什么要单独做这一步**：开发机上很多东西是"理所当然"的 ——
JDK 早就装好了、Ollama 一直开着、模型几个月前就拉过、`.env` 早配好了、
Maven 缓存是热的。这些在别人机器上全都不存在。缺任何一样，在开发机上都不会暴露。

**怎么用**：从上往下做，每步打勾。**卡住的地方原样记下来**（哪怕只是"报错看不懂"）——
卡点就是 README 的缺陷，比"跑通了"更有价值。最后把记录回填到 README 里。

## 1. 解压

- [ ] 解压到一个普通目录，能正常展开
- [ ] 再解压到**路径带中文和空格**的目录（如 `D:\我的 项目\`）—— 程序能不能跑
- [ ] 核对文件完整性：
      - Windows：`certutil -hashfile qa-assistant-1.0.0-SNAPSHOT.jar SHA256`
      - Linux/macOS：`sha256sum -c SHA256SUMS.txt`
      和 `SHA256SUMS.txt` 里的值一致
- [ ] **包里不应该有 `.env`**（有的话说明出包有问题，请反馈）

## 2. 装 JDK

- [ ] 先**不装**，直接双击 `start.cmd` / 跑 `./start.sh`，看提示是否可照做
      （期望：明确说"需要 JDK 17+"并给下载地址，而不是抛 `UnsupportedClassVersionError`）
- [ ] 装上 JDK 17 或更高，重跑，脚本应识别出来
- [ ] 记一下：你从 README 的哪句话知道该装哪个版本的？

## 3. 启动

Windows：

- [ ] **双击** `start.cmd` 能跑起来（不需要先开命令行、不需要改路径）
- [ ] 中文提示**不乱码**
- [ ] 大约 8 秒后浏览器自动打开 `http://localhost:8080`
- [ ] 换端口可用：`start.cmd 8081`
- [ ] 手动占住 8080 再启动，提示是否说清"端口被占用、换个端口"

Linux / macOS：

- [ ] `chmod +x start.sh && ./start.sh` 能跑起来
- [ ] `file start.sh` 确认是 LF 换行（不是 CRLF）
- [ ] 有 `xdg-open` / `open` 时会自动开浏览器

## 4. 首次运行（空数据目录）

- [ ] 启动前确认本机没有 `~/.qa-assistant`（有就先改名备份）
- [ ] 启动后它被自动创建，里面应有 `data/`、`uploads/`、`index/`、`logs/`
- [ ] 「系统状态」页显示的**数据目录**和实际路径一致

## 5. 本地模型（选做，有显卡再做）

如果这台机器没有独显，**跳过这节**，直接走第 6 节用云端模式。

> ⚠️ 这一节里第 2 条（`ollama create qa-embed:4b …`）**不能跳过**。
> 本机模式的默认向量模型就是 `qa-embed:4b`，没有这个模型向量检索起不来。
> 它是从 `qwen3-embedding:4b` 派生的，不额外下载权重，一条命令的事。

- [ ] 按 README 拉两个模型：`qwen3.5:9b` 和 `qwen3-embedding:4b`
- [ ] 按 README 生成派生向量模型：`ollama create qa-embed:4b -f deploy/ollama/Modelfile.qa-embed`
- [ ] `ollama ps` 里两个模型**同时在列**（不在列说明漏了上一步，会导致每问一次都重载）
- [ ] 启动日志里 `num-ctx` 显示的是**具体数字**（如 `16384（auto：按显存自动选定）`），
      不是 `auto` 字样
- [ ] 无独显机器上，日志应提示"使用保守值 4096，建议改用云端模式"

## 6. 云端模式（选做，有 API Key 再做）

- [ ] 照 README 复制 `.env.example` 为 `.env`，填 Key
- [ ] 界面「模型来源」里能切到云端，切换后页面自动刷新、页头显示"云端"
- [ ] 问一次，回答正常，页头有"数据会发送给云端"的警示
- [ ] 「系统状态」点连通性自检，两个端点都显示通过
- [ ] **故意把 Key 改错**，重启，再提问 ——
      应看到"模型服务拒绝了当前 API Key（401）…"这样的提示，
      **不是**"系统内部错误"
- [ ] 改回正确 Key、重启，自检恢复通过

## 7. 端到端问答（核心）

- [ ] 传一份你自己的文档（docx 或 pdf），状态变成"已入库"
- [ ] 问一个**只有那份文档里才有**的答案 —— 回答正确
- [ ] 展开「引用来源」能看到**真实文件名**
- [ ] 问一个文档里**没有**的问题 —— 回答是"未找到"，**不是**编造
- [ ] 连问 3 轮，第 3 轮问"我第 1 轮问的是什么" —— 能答对（会话记忆）
- [ ] **回答完整性**（v1.23 新增）：问一个「有哪些 / 分别是什么」这类要求列举的问题 ——
      回答应把知识库里的相关条目都列出来，而不是只答一两条；
      再问一个库里确实没有的 —— 回答是「未找到」，且**不再附一大段解释**
- [ ] **记忆删除必须真的生效**（分两层验，v1.24 才补齐第二层）：
      ① **数据层**：删掉一条记忆后刷新页面，它**不应重新出现**；重启应用后也不应出现。
      ② **行为层（关键）**：先在一条会话里让助手形成某个习惯（例如说"以后每次回答末尾加个喵~"，等它照做 2~3 轮），
      再去「记忆管理」删掉这条记忆，**在同一条会话里**继续提问 ——
      从删除后的**下一轮起**就不应再带那个习惯（实测 10/10）。
      若仍偶发出现，开一个新会话复核：新会话不带旧历史，行为应立刻回到默认
- [ ] 系统状态页：`运行状态` 与 `生效参数` 是**单列铺开**的，每个字段的说明文字独占一行、
      不出现需要横向滚动的窄框
- [ ] 刷新页面，会话和消息还在
- [ ] 新开一个会话，说"以后回答简短点"，**再开一个会话**提问 —— 回答明显变短（长期记忆）
- [ ] 「记忆管理」页能看到那条记忆；删掉后，新会话里立刻不再生效

## 8. 扫描版 PDF（选做）

> ⚠️ 先分清两件事：**解析失败**和**装没装 OCR 依赖无关** —— 扫描件没有文字层，
> 上传后必然显示"失败"，装了依赖也一样。依赖只决定失败之后能不能救回来。

### 8.1 先在干净 venv 里验依赖清单（**这一步不能跳**）

> 为什么要单独建 venv：开发机上往往早就装过 `onnxruntime`（折腾 PaddleOCR 之类留下的），
> 于是"依赖清单漏了它"这种 bug **在开发机上永远暴露不出来**。
> 必须用一个全新的 Python 环境，才能验出清单本身对不对。

```cmd
cd /d D:\qa-assistant
python -m venv %TEMP%\qa-ocr-test
%TEMP%\qa-ocr-test\Scripts\python.exe -m pip install -r deploy\ocr\requirements.txt
%TEMP%\qa-ocr-test\Scripts\python.exe deploy\ocr\qa_ocr.py --check
```

- [ ] 最后一条命令输出 `{"ok": true, ...}`（**这是硬门槛**）
- [ ] 输出里 `versions` 含**三个**键：`rapidocr` / `pymupdf` / `onnxruntime`
      —— 少任何一个都说明 `requirements.txt` 漏了包
- [ ] 全部装完后 `%TEMP%\qa-ocr-test` 可以直接删掉（它只用来验清单）

### 8.2 用真实环境走一遍界面流程

- [ ] 传一份扫描件或手机拍的 PDF —— **不用点任何按钮**，等几秒后状态标签自己变成
      **「待确认」**（黄色），"失败原因"列写"已自动识别出 N 字，待你确认后入库"
- [ ] 页面**不需要手动刷新**（有文档在 PENDING/PARSING 时前端每 2 秒轮询一次）
- [ ] 按 README 第 8 节的**四步**装 OCR 依赖（关键是先 `cd /d` 到程序目录，
      再用 `python -m pip install -r deploy\ocr\requirements.txt`）
      —— 这一步要联网；脚本随发布包分发，就在 `deploy/ocr/`
- [ ] 装完跑自检（**三个包都要查**）：
      `python -c "import sys, rapidocr, onnxruntime, pymupdf; print('OK'); print(sys.executable)"`
- [ ] **没装依赖时的表现**（先在装之前试）：状态是"失败"，原因写"自动识别未成功：…"，
      **文档没有被判死**；刷新页面（F5）后「识别文字」按钮可点（探测缓存 5 秒，不需重启应用）
- [ ] 点「查看识别结果」，弹出确认对话框
- [ ] 对话框里有：页数、**有字页数**、**内嵌插图统计**、字数、平均置信度、识别文本预览
- [ ] **插图那一路**：拿一份"文字层正文 + 一张小小的截图"的 PDF，点「识别文字」后，
      截图上的字应出现在识别结果里 —— 这一条**用 --detect-images off 对照**：
      关掉后同一条内容就不该出现（说明图片路径确实在起作用）
- [ ] 同一份文件里"整页渲染已经读到的插图文字"**不应重复出现两遍**
      （对话框的"内嵌插图"一栏会显示"其文字已包含在页面识别结果中"）
- [ ] 点「确认入库」，状态变"已入库"，失败原因列显示"正文来自本机 OCR 识别…"
- [ ] 去对话页问一个只有那份扫描件里才有的内容 —— 能检索到
      > ⚠️ **小文档要挑对问题**：相似度分数跟知识库规模强相关（几百块的库 0.80~0.85，
      > 只有一两块的小文档 0.67~0.78）。默认阈值已按此定为 `0.65`；
      > 若你的库以短文档为主，问一句"资料里明确写了的那句话"，而不是"概括一下这份文件"。
      > 检索不到时，先用 `POST /api/v1/documents/search` 传 `minScore=0` 看**实际分数**，
      > 再决定是调阈值还是改资料 —— 别盲猜。
- [ ] **不装 Python 的情况**：按钮应置灰，提示里给出**能在程序目录直接照抄**的安装命令，
      其余功能完全不受影响

### 8.3 图片文件（jpg / jpeg / png / webp / bmp）

> 图片与扫描件是**同一条路**：都没有文字层，上传后都会**自动识别一次**、状态变「待确认」，
> 核对后确认才入库。所以 8.2 的流程对图片同样适用，下面只列图片特有的检查点。

- [ ] 五种格式都能上传成功（前端选择框里能选到，不是被 `accept` 挡在外面）
- [ ] 上传后**不用点任何按钮**，等几秒状态标签变成「待确认」，原因列写"已自动识别出 N 字…"
- [ ] 按钮文案是「**查看识别结果**」（不是「识别文字」）—— 点它应该**秒开**，
      不是再等一遍识别（后端有缓存回放；日志里会有一条"复用未过期的识别结果"）
- [ ] 识别结果里的中文与数字都正确 —— 建议用一张含**编号/日期**的图，
      逐字比对（如 `EQ-2043-A7`、`SN-88231`、`2026-10-11`、`GB/T 19001-2016`）
- [ ] 确认入库后状态变「已入库」，失败原因列显示"正文来自本机 OCR 识别…"
- [ ] 传一张**纯照片**（风景、人脸）→ 状态"失败"，原因写"已自动识别，但这份文件里
      没有读出任何文字（可能是纯图片、空白页或字迹过于模糊）"，而不是崩掉或空结果
- [ ] **白名单一致性**：改动 `qa.allowed-extensions` 或 `qa.ocr.recognizable-extensions`
      任一配置后，两边必须同步 —— 前者多出格式而后者没有，会产生
      "能上传、解析必然失败、识别按钮却永远置灰"的死角
      （`DocumentServiceUploadTest.imageFormatsMustAlsoBeOcrRecognizable` 会拦这一条）

## 9. 文件格式与不支持场景

- [ ] 七种文字型格式都能上传成功：`txt` / `md` / `docx` / **`doc`** / `pdf` / `xlsx` / `html`
      （`.doc` 是 Word 97-2003 老式二进制，用一份**真实的** .doc 验，别用改名文件）
- [ ] 五种图片格式都能上传成功：`jpg` / `jpeg` / `png` / `webp` / `bmp`
      （详见 8.3；它们上传后**必然**解析失败，这是预期行为）
- [ ] `.doc` 入库后能被检索命中，且正文**没有乱码**
- [ ] 传超过 50MB 的文件 → 提示超过大小限制
- [ ] 传一个不支持的扩展名（如 `.zip`）→ 报错话术应**明确区分**"不支持什么"和"支持什么"，
      支持清单顺序应稳定且可读
- [ ] 传手写体或印章的照片 → 识别质量差时对话框应有黄字提醒（说明"必须人工确认"这道闸门有效）
