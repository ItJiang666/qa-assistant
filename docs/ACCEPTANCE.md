# 干净机器验收清单

在没装过本项目的机器上，只按 [README](../README.md) 操作一遍，确认可以正常跑起来。

用法：从上往下执行，逐项打勾。卡住的步骤原样记录报错与现场，这些是文档需要补充的地方。

---

## 开始之前

| 项 | 说明 |
|---|---|
| 目标机 | 未装过本项目，建议也没装 JDK 与 Ollama |
| 准备 | 出包脚本产出的 `release/qa-assistant-*.zip`，以及 `README.md` |
| 通过标准 | 全程只看 README，能打开页面并得到一次带出处的回答 |
| 建议记录 | 从解压到第一次成功问答的耗时 |

## 1. 解压

- [ ] 解压到普通目录，能正常展开
- [ ] 再解压到带中文和空格的路径（如 `D:\我的 项目\`），程序能运行
- [ ] 核对文件完整性
      - Windows：`certutil -hashfile qa-assistant-1.0.0-SNAPSHOT.jar SHA256`
      - Linux / macOS：`sha256sum -c SHA256SUMS.txt`
      与 `SHA256SUMS.txt` 中的值一致
- [ ] 包内不含 `.env`

## 2. JDK

- [ ] 先不装 JDK，直接运行 `start.cmd` / `start.sh`，提示应说明需要 JDK 17+ 并给出下载地址
- [ ] 安装 JDK 17 或更高版本后重跑，脚本能识别
- [ ] 记录：从 README 的哪一句得知需要安装哪个版本

## 3. 启动

Windows：

- [ ] 双击 `start.cmd` 能启动
- [ ] 中文提示不乱码
- [ ] 约 8 秒后自动打开 `http://localhost:8080`
- [ ] `start.cmd 8081` 可更换端口
- [ ] 手动占用 8080 后启动，提示说明端口被占用并给出换端口建议

Linux / macOS：

- [ ] `chmod +x start.sh && ./start.sh` 能启动
- [ ] `file start.sh` 显示 LF 换行
- [ ] 存在 `xdg-open` / `open` 时自动打开浏览器

## 4. 首次运行

- [ ] 启动前确认本机没有 `~/.qa-assistant`（有则改名备份）
- [ ] 启动后该目录自动创建，包含 `data/`、`uploads/`、`index/`、`logs/`
- [ ] 「系统状态」页显示的数据目录与实际路径一致

## 5. 本地模型（有独立显卡时）

无独显可跳过本节，直接做第 6 节。

- [ ] 按 README 拉取 `qwen3.5:9b` 与 `qwen3-embedding:4b`
- [ ] 生成派生向量模型：`ollama create qa-embed:4b -f deploy/ollama/Modelfile.qa-embed`
- [ ] `ollama ps` 中两个模型同时在列
- [ ] 启动日志里 `num-ctx` 显示具体数值（如 `16384（auto：按显存自动选定）`）
- [ ] 无独显机器上，日志提示使用保守值 4096

## 6. 云端模式（有 API Key 时）

- [ ] 复制 `.env.example` 为 `.env`，填写 Key
- [ ] 「模型来源」可切到云端，页面刷新后页头显示"云端"
- [ ] 提问能正常回答，页头有数据外发提示
- [ ] 「系统状态」连通性自检两个端点均通过
- [ ] 故意填错 Key 后重启再提问，提示为"模型服务拒绝了当前 API Key（401）…"而不是内部错误
- [ ] 改回正确 Key 重启，自检恢复通过

## 7. 端到端问答

- [ ] 上传一份 docx 或 pdf，状态变为"已入库"
- [ ] 提问仅在文档中出现的内容，回答正确
- [ ] 展开「引用来源」能看到真实文件名
- [ ] 提问文档未涉及的内容，回答"未找到"，未编造
- [ ] 连续提问三轮，第三轮问"我第 1 轮问的是什么"，回答正确
- [ ] 提问"有哪些""分别是什么"这类列举问题，回答覆盖知识库中的相关条目
- [ ] 删除记忆后刷新页面，该记忆不再出现；重启后也不出现
- [ ] 在一条会话中让助手形成某个习惯，删除该记忆后同一会话下一轮起不再沿用
- [ ] 「系统状态」的「运行状态」与「生效参数」为单列铺开，无需横向滚动
- [ ] 刷新页面后会话与消息仍在
- [ ] 新开会话说"以后回答简短点"，再开一个会话提问，回答明显变短
- [ ] 「记忆管理」能看到该记忆，删除后新会话立即不再生效

## 8. 扫描版 PDF

扫描件没有文字层，上传后显示"失败"属预期。装与不装 OCR 依赖都是这个结果，依赖只决定失败后能否恢复。

### 8.1 在干净 venv 中验证依赖清单

```cmd
cd /d D:\qa-assistant
python -m venv %TEMP%\qa-ocr-test
%TEMP%\qa-ocr-test\Scripts\python.exe -m pip install -r deploy\ocr\requirements.txt
%TEMP%\qa-ocr-test\Scripts\python.exe deploy\ocr\qa_ocr.py --check
```

- [ ] 最后一条输出 `{"ok": true, ...}`
- [ ] 输出中 `versions` 含三个键：`rapidocr`、`pymupdf`、`onnxruntime`
- [ ] 验证完成后可删除 `%TEMP%\qa-ocr-test`

### 8.2 界面流程

- [ ] 上传扫描件或拍照 PDF，等待数秒后状态自动变为「待确认」，失败原因列写明已识别字数
- [ ] 页面无需手动刷新（存在 PENDING / PARSING 文档时前端每 2 秒轮询）
- [ ] 按 README 安装 OCR 依赖，装完点击「系统状态」的连通性自检
- [ ] 未装依赖时上传扫描件：状态失败，注明自动识别未成功，文档未被判死；刷新页面后「识别文字」按钮可点
- [ ] 点「查看识别结果」弹出确认对话框
- [ ] 对话框包含页数、有字页数、内嵌插图统计、字数、平均置信度、文本预览
- [ ] 用"文字层正文 + 一张小截图"的 PDF 验证插图通道：截图上的字出现在结果中；用 `--detect-images off` 对照时应消失
- [ ] 整页渲染已读到的插图文字不重复出现
- [ ] 点「确认入库」后状态变为"已入库"，失败原因列注明正文来自本机 OCR 识别
- [ ] 在对话页提问只有该扫描件才有的内容，能检索到
- [ ] 未装 Python 时识别按钮置灰，提示中给出可直接复制的安装命令，其余功能正常

小文档检索不到时，先用 `POST /api/v1/documents/search` 传 `minScore=0` 查看实际分数，再决定调整阈值还是更换资料。

### 8.3 图片文件

图片与扫描件走同一条路径，8.2 的流程同样适用，以下为图片特有的检查点。

- [ ] 五种格式（jpg / jpeg / png / webp / bmp）都能上传
- [ ] 上传后状态自动变为「待确认」
- [ ] 按钮文案为「查看识别结果」，点击后立即展示缓存结果，不重新识别
- [ ] 用含编号与日期的图片逐字核对识别结果（如 `EQ-2043-A7`、`SN-88231`、`2026-10-11`、`GB/T 19001-2016`）
- [ ] 确认入库后状态变为"已入库"
- [ ] 上传纯照片（风景、人脸）显示失败，原因说明未读出文字
- [ ] 修改 `qa.allowed-extensions` 或 `qa.ocr.recognizable-extensions` 时两者保持同步
      （`DocumentServiceUploadTest.imageFormatsMustAlsoBeOcrRecognizable` 覆盖此项）

## 9. 文件格式与不支持场景

- [ ] 七种文字型格式均可上传：txt / md / docx / doc / pdf / xlsx / html
      （`.doc` 用真实的 Word 97-2003 文件验证）
- [ ] 五种图片格式均可上传
- [ ] `.doc` 入库后能被检索命中，正文无乱码
- [ ] 上传超过 50 MB 的文件，提示超过大小限制
- [ ] 上传不支持的扩展名（如 `.zip`），提示区分"不支持什么"与"支持什么"
- [ ] 上传手写体或印章照片，识别质量差时对话框给出黄字提醒

## 10. 出包脚本（可选）

- [ ] 在装有 Maven 的机器上运行 `package-release.cmd` / `./package-release.sh`
- [ ] 产出 zip 与 `.sha256`
- [ ] 输出中无"存在敏感文件"的拒绝提示，包内清单不含 `.env`
- [ ] 包内清单包含 `deploy/ocr/` 与 `deploy/ollama/Modelfile.qa-embed`
